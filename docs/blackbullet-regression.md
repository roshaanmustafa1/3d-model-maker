# Rendering and material regression

## Confirmed code defects

- Import retained only material slot 0, discarded all texture references and physical material extensions, and reconstructed every material as MeshStandardMaterial. Multi-material assignments and textured appearance could not survive that conversion.
- Stored material wireframe flags affected both Solid mode and export. Wireframe now belongs to the viewport; legacy flags are ignored with an export warning.
- Root transforms were discarded for grouped imports and non-XYZ Euler orders were not preserved. Selected export also dropped ancestor transforms.
- Selection edges were drawn through surfaces because depth testing was disabled. Selection uses separate line geometry and now respects surface depth.
- Export verification previously checked only parseability, mesh/triangle counts and UV presence. It did not compare material values with the source.

These findings do **not** establish the cause of the reported T-shirt's missing surfaces or downstream white fabric: neither that asset nor the separate BlackBullet application exists in this workspace. Scalar black PBR color was already copied by the original importer; a uniform black-to-white failure must not be attributed to GLTFExporter without the affected asset and downstream trace.

## Implementation

Imported material clones retain their class, original texture objects, sampler/UV settings, alpha and physical properties. Editor fields override the supported properties explicitly; unedited linear color components retain full precision. Mesh material arrays and geometry groups stay aligned. Explicit texture removal uses null; undefined retains the imported texture. Uploaded texture loads finish before export starts. Material assignment and viewport toggles remain supported.

Solid and Material Preview both display the original PBR surface. Wireframe and Normal Visualization create disposable viewport-only materials for every slot. Selection materials never enter the scene builder or exporter. No global DoubleSide, index reversal, or normal recalculation is applied. Missing normals continue to be generated by the existing geometry registration layer.

Validation now inspects real position/normal/UV attributes, triangle indices, degenerate faces, zero normals, missing material slots, visibility, finite/singular transforms, mirrored determinants and unexpected wireframe. Export reimports with GLTFLoader and compares logical node IDs, parent relationships, names, customization metadata, world matrices, material names/types/colors/PBR values/alpha/side, common texture slots/settings and per-triangle position/normal/UV data. It allows glTF multi-primitive splitting while checking each primitive against its original geometry group. Negative determinants are warnings; singular transforms are errors. Export results expose actual glTF materials in `exportedMaterials` and show errors and warnings separately in the report data.

## Reproduce and check

Requires Node 22.15+ or 24+ for registerHooks, plus the already-installed dependencies.

```powershell
npm test
npm run typecheck
npm run build
node --import ./scripts/register-typescript.mjs scripts/export-black-shirt.mjs
```

`fixtures/black-shirt.glb` is a synthetic three-part box-based T-shirt silhouette, not the reported garment. `fixtures/black-shirt-materials.json` is extracted from the actual exported GLB JSON. Its named material is Matte Black Cotton, base color #111111, roughness 0.85 and metalness 0. glTF stores baseColorFactor in linear color space, so its RGB numbers differ from 17/255.

Automated tests use the real GLTFExporter and GLTFLoader; Node supplies a FileReader adapter over real Blob bytes. Tests cover GLB import/export/reimport, grouped materials, physical material reconstruction and texture object preservation, precise color values, explicit map removal, corruption detection, mirrored and selected-object transforms, and all viewport modes. Raycasting checks six directions and a 360-degree horizontal orbit. DoubleSide is applied temporarily in that diagnostic test and restored. Raycasting does not verify WebGL pixels or lighting. Texture image encoding/decoding is not exercised by the Node tests.

## Remaining asset and BlackBullet checks

1. Import the affected T-shirt. Inspect source and imported material names/UUIDs/classes, linear colors, maps/color spaces, opacity/alpha/side, groups and transforms. UUIDs are runtime identities and can change on clone/reload; mesh node IDs and material assignments provide the comparison identity.
2. Inspect Solid, Material Preview, Wireframe and Normal modes from front/back/left/right/top/bottom and a full orbit. If an affected face appears only with a temporary DoubleSide diagnostic, inspect its winding, normals and mirrored parents before repairing that geometry. Restore the original side afterward.
3. Export, review errors/warnings and inspect `exportedMaterials` against the actual GLB material factors and texture references. Repeat with textured garments to verify real image encoding/decoding and sampler behavior.
4. Load the standalone fixture and affected GLB in the actual BlackBullet codebase. Log each mesh's material immediately after GLTFLoader, after fabric initialization, after zone assignment and after default color selection. Preserve imported base color, maps, roughness and metalness until an explicit user action changes them. Do not initialize a white selection by assigning it automatically to loaded materials.
5. Confirm geometry primitive mode is TRIANGLES, world transforms/normals are respected, names and glTF extras identify customization zones, and no startup material replacement clears imported textures or factors. Compare screenshots of all six directions only when browser testing is authorized.

## Limits

The existing project persistence stores custom geometry references rather than geometry bytes. Imported source material references are likewise session resources. Reloading such projects across sessions still requires reimporting the source asset; a missing source material now raises an explicit error instead of silently becoming a default material. Durable asset persistence is a separate change. Skinned/animated models and arbitrary unsupported material/texture extensions are not certified by this static-mesh regression suite. A round-trip mismatch is reported instead of claiming compatibility.

Browser verification was not performed, in accordance with project instructions. BlackBullet compatibility and the reported garment's visual defects remain unverified until the actual asset and consumer are available.
